# 03. Расстояние до цели D

Реализация: `src/scc/geometry/distance.py`.

D нельзя надёжно мерить как семантическое расстояние между текстом контекста и текстом цели.
Его определяем как агрегат по **проверяемым координатам**.

## 1. D_completion — по требованиям

```
G = (g_1..g_n),  S_t = (s_1..s_n)
D(S_t, G) = sqrt( Σ w_i · d_i(s_i, g_i)^2 )
Progress  = Σ w_i q_i / Σ w_i,   q_i ∈ [0,1]
D_completion = 1 − Progress
```

`q_i` — из verifiers, не из самооценки LLM:
`s_tests = passed/required`, `s_API = verified_endpoints/required`, `s_req = Σ w_i·verified_i / Σ w_i`.

Hard constraints: если любой `H_j = 0`, цель не достигнута независимо от средней (critical bug блокирует delivery).

Пример:

| Координата | Вес | Состояние |
|---|---|---|
| Архитектура | 0.10 | 100% |
| Backend | 0.25 | 70% |
| Frontend | 0.20 | 40% |
| Tests | 0.20 | 50% |
| Security | 0.10 | 20% |
| Документация | 0.05 | 80% |
| Acceptance | 0.10 | 60% |

## 2. D_cost — cost-to-go

```
D*(S, G) = min_{π: S→G} E[ Cost(π) ]
Cost(π)  = α·Tokens + β·Steps + γ·$ + δ·Time + ε·Risk
```
Центральное определение: **минимальная ожидаемая стоимость перехода в любое состояние из G**.
Точно неизвестна — контроллер хранит оценку `D̂` и обновляет её после каждого действия.

## 3. U_D — неопределённость оценки

`D_t = 0.37 ± 0.11` или интервал `[0.26, 0.48]`. Исследование может почти не менять центр D,
но резко снизить U — это реальный прогресс.

## Итог

```
D(S, G) = (D_completion, D_cost, U_D)
```

**D может расти**: обнаружена скрытая зависимость → `D̂: 51 → 67`, но `U: 0.40 → 0.12`.
Это коррекция карты, а не регресс.

Четыре различимые ситуации:
1. далеко от цели (D_completion велико);
2. дорого добраться (D_cost велико);
3. неизвестно, насколько далеко (U_D велико);
4. контекст огромен, расстояние почти не сокращается (inflation).

Отображение: положение точки = completion; траектория = cost-to-go; ореол = uncertainty.
